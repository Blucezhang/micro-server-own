已落实：

1. `own-order` 从受控售后单生成退款归属，`own-settlement` 校验该归属对应原付款和原商家应收；同次更新 DTO、客户端、服务端、账本、夹具与文档，移除旧的无归属写入契约。

3. 先定义历史数据可确定/不可确定的分类与迁移步骤，再施加新约束；保留原账本事实，不虚构商家 ID 或将未知退款默认归给某商家。

## C3：收敛商品改价与审计的双库一致性

优先级：高。状态：静态风险已确认，事实所有者与恢复方案未实现。

当前缺口：`MerchantProductController.update` 先经 `ProductDao` 写 Neo4j，再经 `ProductPriceAuditRepository` 写 MySQL；审计写入失败不能原子回滚已经提交的商品改价。

实施顺序：

1. 选定价格变更的唯一事实所有者，明确另一数据库是审计或投影；将变更命令、旧新价格、操作者、原因与业务键作为一份可恢复事实处理。
2. 用该事实所有者的事务保证本地原子性，建立另一侧的幂等投影/恢复；删除原来直接双写却无恢复记录的路径。
3. 明确调用方在一侧成功、另一侧未完成时看到的状态及查询方式，不能把单次补写或异常吞掉称作双库原子事务。

代码完成标准：覆盖商品写入失败、审计/投影写入失败、远端成功后响应丢失、重放与并发改价冲突；每次改价具有可追溯事实或明确未完成状态。Neo4j 与 MySQL 的真实故障回滚仍需另行执行才能验证。
