# 商品更新与价格审计一致性

更新：2026-10-25。实现范围为当前商城商品接口；按用户确认停用旧版商品写入口。未执行真实 Neo4j/MySQL 迁移或联调。

## 当前契约

Neo4j 继续拥有商品事实，不把价格迁到 MySQL。商品更新在明确的 `neo4jTransactionManager` 事务中取得商品写锁、核对商家、保存商品并保存 `ProductPriceChangeEvent`。任何一步失败均向该事务边界传播；不再由控制器先写商品再直接写 SQL 审计。

变更事件保留旧/新价格、归属、原因、整秒时间、请求指纹与返回商品快照。业务键由商家、商品及 `Idempotency-Key` 派生；同键同请求返回原快照，同键异请求拒绝。每次新的逻辑修改必须使用新 key，即使 HTTP 响应缓存已过期，事件键也不用于第二次修改。未改价的编辑也保存重放事实，但不生成价格审计。

`priceWriteRevision` 用于 Cypher 写锁协调，不是公开商品版本号；锁请求（包括重放）可能递增它，API 序列化不暴露该字段。上下架使用相同商品锁，避免用旧商品快照覆盖并发价格。

MySQL `prd_product_price_audit` 是可重建的审计投影，不是第二份价格事实。投影在独立 JPA 事务中按 `event_key` 唯一去重并核对不可变字段，提交后才通过另一个图事务确认完成。SQL 失败或图确认失败都保留待投影事件；定时器每批最多 50 条、逐条记录失败并重试。接口仍返回已提交商品，SQL 审计短暂不可见不等于商品保存失败，也不伪造已完成审计。

## 旧入口停用

移除 `PUT /product/addProduct`、`POST /product/{id}`、`DELETE /product/{id}`；直接控制器检查返回 404，网关拒绝这些写入。保留旧商品读取和独立的商品模板维护能力。未使用的旧 `ProductFace.addProduct/updProduct` 客户端方法移除，未将营销域的活动商品接口误当作目录商品接口删除。

新增、编辑、上下架统一使用 `/product/api/v1/merchant/products` 既有商城契约；不再允许通过旧写入口直接变更商品归属。没有新增商品硬删除 API；现有商城下架能力保留。

## 部署与历史

1. 暂停商品写入，备份并验证恢复方案。
2. 前向执行 MySQL `40-product-price-audit-event.sql`，新增可空 `event_key` 及唯一索引。历史审计保持 NULL，不编造历史事件键。
3. 在 Neo4j 执行 `database/neo4j/price-change-event-constraint.cypher`，使用 3.5 兼容的唯一约束语法。脚本要求执行一次；未声称在真实数据库运行成功。
4. 协调部署并复核事件、投影与旧入口停用；不混跑仍直接双写或可改归属的旧代码。事件待投影时不能通过删除事件、手工改完成状态或降级旧写路径恢复。
