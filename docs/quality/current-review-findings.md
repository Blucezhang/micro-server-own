## 下一轮优先顺序

1. **P1：不确定幂等结果的对账恢复。** PROCESSING 记录现已禁止因过期自动解锁，但没有人工对账/恢复入口。必须先核对业务记录，再决定完成响应或允许重试，不能自动解锁或虚构成功结果。业务自身跨库部分提交后抛错的情况也仍需审查。
2. **P1：真实依赖验收。** 用户服务双事务管理器的完整 Spring Boot 启动、Neo4j 第二笔写入失败后的零残留、MySQL 幂等响应、完整下单/退款/库存补偿需在隔离依赖环境执行。商品/促销服务的图谱与 JPA 管理器选择也需核验，不能沿用默认管理器即认为正确。
3. **P2：其他页面的移动端验收。** 更正此前判断：手机冷启动与等待响应式更新后的断点切换均正常，旧截图捕获了切换瞬间。真实缺陷为长商品数据撑宽业务区域，本轮已修复。购物车、订单详情、发货与治理表格仍需逐页检查，不把商品页验证推广为全站验收。
4. **P2：系统管理能力缺口。** 当前账号/角色页面明确提示未提供列表接口，靠手工输入审核过的 ID 授权；尚缺可搜索列表、当前授权展示与撤销流程。需先定义后端契约，再实现 UI，不能把现有追加授权描述为完整权限管理。
